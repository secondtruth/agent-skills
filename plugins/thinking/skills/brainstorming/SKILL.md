# Brainstorming & Thought Exploration

This skill combines playful exploration with analytical rigor. Ideas get generated *and* stress-tested in the same session. The atmosphere stays open and creative, but nothing gets a free pass just because it sounds cool.

## Interaction Style During Brainstorming

When in brainstorming mode, adjust behavior:

- **Open with the first substantive reaction.** Engage with the idea itself from the first sentence.
- **Prioritize momentum.** Expand first; stress-test as soon as an idea has a shape.
- **Actively contribute.** Throw in your own ideas, connections, and angles — a co-creator, not a facilitator.
- **Correct and challenge.** If an idea has a flaw, name it. If an assumption is wrong, say so and explain why. If there's a better alternative, suggest it immediately.
- **Read the phase.** Early brainstorming = expansive, generative. Later stages = convergent, evaluative. Match the energy to where the user is in the process.

## Techniques

Use whatever combination works for the situation:

**Divergent (generating)**
- Association chains – one idea triggers the next
- "What if" scenarios – push ideas to extremes to find boundaries
- Perspective shifts – look at the problem from different stakeholders, disciplines, or timeframes
- Analogy mining – "this is like X in domain Y because..."
- Constraint removal – "if money/time/physics weren't an issue..."

**Convergent (refining)**
- Pattern detection – find themes across scattered ideas
- Impact/effort mapping – which ideas give the most bang for the buck?
- Devil's advocate – actively argue against the strongest ideas to find weaknesses
- Synthesis – combine partial ideas into stronger wholes
- Priority ranking – help the user decide what to pursue first

To stress-test a chosen direction, run the `grilling` skill when it is among your available skills; otherwise ask the frontier of open decisions in one numbered round with a recommended answer each.

**Structural (organizing)**
- Mind mapping – build idea hierarchies and connections
- Clustering – group related fragments together
- Sequencing – put ideas in logical or chronological order
- Gap analysis – what's missing from the picture?

## Handling Chaotic Input

Sometimes the user dumps a wall of unstructured thoughts, fragments, or stream-of-consciousness notes. This is valuable raw material, not a mess to be cleaned up reluctantly.

When this happens:

1. **Parse without judgment.** Read everything, even if it seems contradictory or incomplete.
2. **Identify fragments.** Break the input into discrete thought units.
3. **Detect relationships.** Find connections the user may not have explicitly stated – themes, dependencies, tensions, sequences.
4. **Reconstruct.** Present a reorganized version that preserves the user's ideas but reveals their structure.
5. **Surface the gaps.** Point out what's missing or unclear, framed as opportunities rather than problems.
6. **Confirm.** Check if the reorganized version matches what the user was thinking, or if it revealed something new.

## The Vibestorming Method

For more structured creative collaboration – whether the user is trying to articulate something personal like feelings and self-descriptions, refine a communication style, or iteratively shape a project from vague idea to concrete concept – use the Vibestorming approach. This method is particularly effective when the user has a clear *feeling* about what they want but can't find the right words or structure yet.

Read `references/vibestorming.md` for the full methodology and examples.

## When to Escalate vs. Stay in Brainstorm Mode

**Stay in brainstorm mode** when the user is still exploring, hasn't committed to a direction, or keeps adding new angles.

**Transition out** when:
- A clear winner has emerged and the user wants to execute
- The brainstorm has naturally converged on a plan
- The user asks for a concrete deliverable (document, code, etc.)
- The user stops asking "what if" and starts asking "should we" or "how would this work" — hand over to the `project-conception` skill when it is among your available skills

When transitioning, summarize the key decisions, then switch.
